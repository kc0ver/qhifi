> 状态：已批准。P0（DSP 内核 + 离线验证 + 接线 + 调试广播）、P1（设置项 + 链路卡片标注）已完成。
> 范围：只覆盖 Android 的 USB 独占输出路径；桌面端不接 UI，但 DSP 内核放在 `player-core`，可在 JVM 上跑离线验证。

| 阶段 | 交付物 | 可独立验收 |

| P0 ✅ | `TubeToneDsp` 内核 + 离线 FFT 验证 + `TubeToneSink` 内挂 `UsbIsoSink` + 调试广播切预设 | 谐波电平符合标定，混叠低于 -80dBFS（6 项单测全绿） |

## 1. 边界与前提

**只做 USB 独占路径。** 框架路径走 `MediaPlayer`，PCM 全程活在系统进程里，应用层拿不到样本；这不是实现难度问题。独占路径的 `sink.write(buffer, size)`（`AndroidDirectAudioBackend` 解码循环内）是唯一现成插点。

三条不能破的规则：

1. **不改格式**。采样率、声道数、位深进出完全一致。一旦变化，USB sink 要重开，等时反馈端点跟着乱。胆味是纯样本域处理，不参与时钟链。
2. **默认关闭，且必须可见**。HiFi 用户的核心诉求是 bit-perfect；胆味是刻意的染色。开启时在音频链路卡片明确显示"胆味 300B · 非 bit-perfect"，不做隐瞒。
3. **关闭时零开销**。不是"处理但混 0%"，而是根本不进入处理函数。

## 2. 音频侧：胆味 DSP

### 2.1 分层

| 文件 | 职责 |
|---|---|
| `player-core/src/main/java/dev/t1m3/qplayer/audio/TubeToneDsp.java` | 纯算法，无 Android 依赖，可在 JVM 上单测 |
| `player-core/src/main/java/dev/t1m3/qplayer/audio/TubeTonePreset.java` | 三种管型的参数表 |
| `android-shell/.../playback/TubeToneSink.java` | 容器转换 + 块处理，挂在 `UsbIsoSink` 内部 |
| `UsbIsoSink.java` | 4 行改动：字段、`open` 后 `configure`、`write` 前 `process`、`flush` 时 `reset` |

**不是装饰器。** 原方案想在 `sink` 外面包一层 `TubeToneSink implements PcmSink`，但 `AndroidDirectAudioBackend` 里有十几处 `sink instanceof UsbIsoSink` 的强转（硬件音量模式、UAC 版本、是否同一个 DAC、`sourceDepth`）。一旦包起来，这些判断全部落空且不报错——音量模式会静默失效。所以改成挂在 `write()` 内部：`sink` 的类型和所有强转都不动，只是送 USB 前多一次块处理。

关闭时 `dsp == null` 或 `enabled == false` 直接返回，`UsbIsoSink.write` 与原来完全一致。

### 2.2 信号链

```
x (float, 交错)
 → pre-gain g
 → [2x 上采样：96 抽头半带 polyphase]
 → 二次项+三次项  s = y + a·y² + b·y³   (b = 0.45a，a 已含强度与包络)
 → 拐点软限幅
 → 一阶高通 20Hz（去非线性产生的 DC）
 → [2x 降采样]
 → 两级 biquad 倾斜
```

**强度怎么实现。** 不做 dry/wet 时域叠加，直接把强度乘进非线性系数 `a`。干湿混合在半湿（55）时会让 dry 与相位偏移后的 wet 在高频互相抵消——实测 8kHz 掉 1.2dB，听感是"声音被困在管子里"，而全湿反而正常。而且 `a→0` 时波形整形本来就退化为线性，不需要混合。频响倾斜也不随强度缩水，否则强度 55 时 300B 的高频架只剩 -0.55dB，开关几乎听不出来。

**为什么是这个顺序。** 二次项是偶次谐波的来源，但它会让峰值爆炸（x=1 时变成 1+a），所以后面必须跟软限幅。限幅用"拐点 + 渐近上限"而不是全程 tanh：正常电平下它是完全线性的，不会在 0.5 电平就把 H3 抬到 H2 之上（全程 tanh 实测 H3 比 H2 高 3dB，听感会更硬）。三次项 b·y³ 单独给出少量奇次谐波，它随电平平方增长、掉得比 H2 快，符合真实胆机。二次项产生的 DC 分量正比于信号功率，必须用高通去掉，否则低电平会推动 DAC 的工作点。

**a 的标定**（a 就是设置页「强度」滑块的物理量）：

| 目标 H2（相对基波） | a |
|---|---|
| -40dB（约 1%） | 0.040 |
| -35dB（约 1.8%） | 0.071 |
| -30dB（约 3%） | 0.126 |

关系是 `a = 4 × 10^(dB/20)`，取参考电平 A_ref = 0.5（-6dBFS）。推导：幅度 A 的正弦过 `y+a·y²` 后，二次分量绝对幅度是 `a·A²/2`，相对基波是 `a·A/2`；所以 H2 **随信号幅度线性增长**，不绑定电平无法标定。低于参考电平时谐波自然减轻，这正是要的"谐波随电平"。

> 注：早期草稿写的是 `a = 2 × 10^(dB/20)`（误把相对量当成绝对量），实测证伪，已修正。

### 2.3 包络调制（决定"像不像"）

静态失真是插件感的主要来源。真实胆机在小信号下其实相当干净，厚暖感只在中高电平浮现。

```
env    = 峰值跟踪（attack 20ms / release 200ms）
a_eff  = a · clamp((env / ref)^0.55, 0.22, 1.0)
```

`ref` 取 -20dBFS 左右；`^0.55` 让胆味在中等电平就出现，而不是只在爆满时。下限 0.22 保证极安静的地方也不是完全死板。指数与下限在真机试听后放宽过一次：原来 `^0.7` / 0.12 让音乐的平均电平段几乎完全没有染色，听感上等于没开。

**验证方法**：拿一段安静人声，强度拉到 100。如果底噪和气息都被"染"了，说明这一步没调对。

### 2.4 频响倾斜

两级 biquad shelf，默认跟随管型预设，可单独关闭：

- 低频架：+1.5dB @ 60Hz，Q 0.707
- 高频架：-1.5dB @ 12kHz，Q 0.707（输出变压器的滚降）

系数只在采样率变化时重算，运行中改参数只更新增益项并做 20ms 平滑。

### 2.5 三种管型

| 参数 | 300B（甜厚） | EL34（通透） | 6L6（均衡） |
|---|---|---|---|
| a（H2 -31 / -37 / -34dB @ -6dBFS） | 0.1127 | 0.0565 | 0.0798 |
| 软限幅拐点 knee | 0.93 | 0.96 | 0.945 |
| 低频架 | +2.0dB @ 150Hz | +0.8dB @ 100Hz | +1.5dB @ 120Hz |
| 高频架 | -1.0dB @ 16kHz | 旁路（不平滚） | -0.6dB @ 16kHz |
| 包络 ref | -22dBFS | -18dBFS | -20dBFS |
| 漂移幅度 | ±0.8% | ±1.2% | ±1.0% |

预设只改这几个系数，成本为零。管型间距按可闻性定：300B 与 EL34 的 H2 差 6dB（实测 -31.1 / -37.0dB），换管型是一耳朵的区别；初版只差 1.5dB，等于没换。

> 量级在真机两轮试听后上移过一次：初版 300B 满标定 -35dB，55% 强度在音乐平均电平处只有约 -50dB，实测听不出任何差别。现在满标定 -31dB（3%），55% 强度在峰值处约 -36dB，中等电平也保留大部分染色（包络指数 0.55、下限 0.22）。

> 参数在 P1 真机试听后修正过一次。初版（knee 0.85~0.95、高频架 -2.2dB @ 11kHz）
> 听感是"罩在罩子里"，客观成因有三：过采样滤波器通带只到 15kHz、高频架起滚太早、
> 软限幅拐点落在 -1.4dBFS 以致正常峰值被压。三者叠加就是高频下陷 + 动态塌陷。

### 2.6 16-bit 路径的量化（已实现）

`TubeToneSink` 在 16-bit 写回前加 TPDF dither：两个 xorshift32 均匀分布相减、幅度 ±1 LSB。不加会在低电平出现量化相关性噪声。这条路径本来就已经不是 bit-perfect，加 dither 反而更干净。

float 路径（`sink.floatPcm()` 为真）不需要 dither。

**注意**：`UsbIsoSink.open()` 之后会被驱动改写实际容器类型（`floatPcm = UacOutput.floatPcm()`），所以 DSP 必须**每块读运行中的实际值**，不能用 open 时请求的那个。

**输出 headroom**：真机实测（44.1k / 16-bit）开胆味时每个 2 秒窗口都有样本撞 32767，关掉后峰值稳定在 0.92。成因是降采样 FIR 的 Gibbs 过冲（约 7%）叠上低频架抬峰，最后的 16-bit 写回硬钳。DSP 在 48k 域最后加了一级软限幅（knee 0.90 / 上限 0.97），保证送去 USB 的样本永远 ≤ -0.26dBFS；实测 `clipped=0` 持续稳定。

### 2.7 线程与性能

- 在喂数据线程内联处理，**不新开线程**。分开会引入缓冲和排序问题。
- `Math.tanh` 在 JVM 上偏慢，改用有理逼近 `x·(27+x²)/(27+9x²)`，音频带宽内误差可忽略。
- 粗算：48kHz 立体声 × 2 倍过采样 ≈ 192k 样本/秒。半带滤波器 96 抽头，上/下采样合计每输入样本约 190 次乘加，单核占用 2% 量级。96kHz 翻倍，仍然远低于喂数据线程的余量（现有环形缓冲约 128ms 队列）。
- 抽头数从初版的 32 提到 96 是 P1 试听后的修正：32 抽头的通带只到 15kHz 左右，单这一项就足以让声音"发闷"。96 抽头把 -1dB 点推到 20kHz 以上，`TubeToneDspTest` 的 `passbandStaysFlatUpToTheTopOctave` 是这一点的准入门槛。

### 2.8 状态重置（最容易出错的地方）

DSP 内部有状态：高通、biquad、包络、mix 平滑器。以下每个时刻都必须 `reset()`：

- `flush()`（seek）
- sink 重开 / 跨曲复用 sink 的边界
- 切歌
- 强度或管型由"关"变"开"

不重置的第一个样本会从旧状态跳变，听感是一次咔哒，严重时是 DC 冲击。

反过来，**参数热更新不能重置**，只能走 20ms 平滑过渡，否则每拖一下滑块就爆一次音。

### 2.9 离线验证（P0 的验收手段）

`TubeToneDsp` 是纯 Java，直接在 `player-core` 里写一个 `main()` 或 JUnit：

1. 生成 1kHz 正弦，喂 1 秒，对输出做 FFT（用 Goertzel 逐频点即可，不引入外部库）。
2. 断言：H2 相对基波符合 2.2 的标定 ±2dB；H3 至少低于 H2 6dB。
3. **混叠测试**：11kHz 单音，48kHz 采样 —— 3 次谐波 33kHz 会折叠到 15kHz。断言折叠峰低于 -80dBFS。这一项决定要不要保留 2 倍过采样。
4. **IMD 测试**：19kHz + 20kHz 双音，看 1kHz 附近的差频产物。
5. 旁路等价性：`enabled=false` 时输出与输入逐字节相同。

### 2.10 真机 A/B

扩展现有调试广播，不建 UI 就能试听：

```
adb shell am broadcast -a dev.t1m3.qplayer.DEBUG --es cmd tube --es arg preset:0
adb shell am broadcast -a dev.t1m3.qplayer.DEBUG --es cmd tube --es arg amount:100
adb shell am broadcast -a dev.t1m3.qplayer.DEBUG --es cmd tube --es arg tilt:on
adb shell am broadcast -a dev.t1m3.qplayer.DEBUG --es cmd tube --es arg drift:on
adb shell am broadcast -a dev.t1m3.qplayer.DEBUG --es cmd tube --es arg on
adb shell am broadcast -a dev.t1m3.qplayer.DEBUG --es cmd tube --es arg off
```

参数在下一个处理块生效（约几毫秒），没有重启流、没有咔哒。`preset` 序号 0/1/2 = 300B/EL34/6L6。`drift:on` 也可用。

状态回显同样走这条命令：返回值里带 `a=<当前非线性系数>`。开着漂移时反复执行，可以看到 `a` 在 ±1% 范围缓慢摆动（`driftMakesTheCoefficientBreathe` 单测即证明这一点，实测 0.11180..0.11345）。这是判断"漂移是否在生效"唯一可靠的手段——它按设计本来就该听不出来。

## 3. 设置项（已实现）

全部落在 `SettingsCatalog` 的 `HIFI` 分类（设置页的 QHIFI 标签），`onlyOn(ANDROID)`，都 `dependsOn("hifiTubeTone")`（开关本身除外）。

| key | 类型 | 默认 | 说明 |
|---|---|---|---|
| `hifiTubeTone` | toggle | false | 总开关 |
| `hifiTubePreset` | segmented | 0 | 0=300B / 1=EL34 / 2=6L6 |
| `hifiTubeAmount` | slider 0–100 | 55 | 强度。55 ≈ -37dB，日常听感的甜点 |
| `hifiTubeTilt` | toggle | true | 是否叠加频响倾斜 |
| `hifiTubeDrift` | toggle | **false** | 缓慢漂移（"呼吸"）。默认关，保证可复现、可回归测试 |

i18n 需要在 `player-core/src/main/resources/lang/zh_CN.properties` 与 `en_US.properties` 两套里加 key。

## 5. 风险清单

| 风险 | 影响 | 处理 |
|---|---|---|
| 混叠伪影（14kHz 附近"沙沙"） | 致命，HiFi 用户一耳朵听出 | P0 的 11kHz 混叠测试是准入门槛；超标就保留 2 倍过采样 |

| 16-bit 路径量化噪声 | 安静段落有颗粒感 | TPDF dither |

## 6. 需要拍板的四处

以下是我按推荐值写进方案的，如果不同意，改动都只涉及参数，不影响架构。

1. **非线性实现**：推荐「波形整形 + 2x 过采样」。理由是 HiFi 定位不能接受混叠伪影，而 128ms 环形缓冲面前这点 CPU 完全负担得起。若你能接受"强度做低就听不出来"，可以退回纯波形整形，省掉半带滤波器。
2. **失真量级**：推荐强度 100 对应 -35dB（约 1.8%，真实单端胆机的典型值），默认强度 55 约 -37dB。
3. **动态处理**：推荐「谐波随电平」（只调制二次项系数，不加压缩器）。若想要更"活"，再加 0.1Hz 级缓慢漂移 + 1.2:1 软压缩，但会失去可回归测试性 —— 已做成默认关闭的开关。
4. **频响倾斜**：推荐"算，且单独可控"，默认跟随管型。若你认为胆味只该是谐波、不该动音色平衡，可以去掉这一级。
